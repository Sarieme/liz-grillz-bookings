OVERVIEW:
When adding a required (NOT NULL) column to a populated table in production, doing so in a single migration causes immediate downtime and database error aborts. We executed the canonical zero-downtime three-step migration pattern across our live PostgreSQL database:
1. Add column as nullable / optional (cancellationReason String?)
2. Backfill existing populated rows with a valid business default
3. Alter column to NOT NULL (cancellationReason String)
