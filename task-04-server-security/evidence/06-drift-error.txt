The column `Booking.driftTestField` does not exist in the current database.

EXPLANATION OF THE TWO THINGS OUT OF STEP:
The two things that have gone out of step are the TypeScript application client layer (in memory and code) and the physical relational database schema (in PostgreSQL on disk). Running `npx prisma generate` reads `schema.prisma` and updates the compiled JavaScript/TypeScript query builder inside `node_modules/@prisma/client`, convincing the compiler and IDE that `Booking.driftTestField` is valid. However, because no SQL DDL migration was applied to PostgreSQL via `prisma migrate dev`, the physical table in PostgreSQL retains its old structure lacking that column. When the runtime client dispatches `SELECT "Booking"."driftTestField" FROM "Booking"`, PostgreSQL rejects the query with an undefined column error (Prisma error code P2022).

RESOLUTION:
To resolve the drift, we removed `driftTestField` from `schema.prisma` and re-ran `npx prisma generate`, restoring perfect synchronization between the application client types and the actual database catalog.
